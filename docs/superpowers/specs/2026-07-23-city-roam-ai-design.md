# 城市漫游 AI 功能设计

## 目标

为“城市漫游”提供两个基于通义千问的 AI 功能：店铺推荐客服和探店点评辅助写作。实现必须保持 Java 8 与 Spring Boot 2.3 兼容，不使用 LangChain4j，也不改变既有业务 API、表结构或 Redis 业务键。

## 架构

后端新增独立的 `ai` 模块。`DashScopeAiClient` 使用 JDK 8 自带的 `HttpURLConnection` 调用阿里云百炼的 OpenAI 兼容流式接口；它只从 `AI_API_KEY` 环境变量读取密钥。`AiConversationService` 用现有 Redis 保存按用户与会话隔离的最近 12 轮消息，设置 24 小时 TTL。

`ShopContextService` 从现有店铺与分类数据检索最多 8 条相关店铺，并只将名称、地址、人均、评分和分类作为可信上下文交给模型。系统提示词必须要求模型仅基于这些内容回答、指出信息缺失，并在无匹配时明确说明未找到结果。模型不能访问数据库、工具调用或业务写操作。

## HTTP 接口

- `POST /ai/chat/stream`：接收用户消息与客户端生成的会话标识，返回 `text/event-stream`。仅面向已登录用户；Redis 键包含用户 ID，防止不同用户复用同一会话标识。
- `POST /ai/review/stream`：接收已选店铺、标题、现有正文和文风选项，返回 `text/event-stream`。服务端使用当前登录用户的会话隔离；生成文本不直接持久化。

两个接口都限制单条输入长度、会话轮数与上下文店铺数量；AI 未启用、缺少密钥、上游超时或返回异常时，以 SSE `error` 事件返回不含敏感信息的用户提示。

## 前端

- 首页加入“城市漫游 AI 向导”入口和移动端浮层。使用原生 `fetch` 读取 SSE 流并逐段显示，不改变既有 Axios 请求、路由或 Vue 数据结构。
- `blog-edit.html` 加入“AI 帮我写点评”按钮和文风选择。生成完成后将文本写入现有正文编辑框，用户可编辑后继续使用现有发布接口。

## 配置与安全

`application.yaml` 只包含非敏感 AI 配置：`ai.enabled`（默认 `false`）、模型名、基础地址、连接超时与读取超时。密钥只来自 `AI_API_KEY` 环境变量，不写入配置、测试、日志、文档或 Git。

## 测试与验收

1. 用可替换的 AI 网关接口和假实现测试店铺检索、提示词约束、用户会话隔离、输入校验及 SSE 错误分支；自动化测试不得发送真实模型请求。
2. 验证已关闭或未设置密钥时 API 不调用上游且返回安全错误。
3. 用本地环境变量手工验证两条流式接口和两个前端入口。
4. 运行 Maven 测试与打包；现有 Redis 集成测试若因外部 Redis 服务不可达失败，记录环境原因但不禁用测试。
